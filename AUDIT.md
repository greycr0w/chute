# chute — Hardening Audit (living document)

**Goal:** make the core chute system *stellar, clean, and simple to understand* — "nginx-level assurance." Correct, robust, minimal, auditable.

**Severity:** HIGH (defect reachable in normal or easy-adversarial use) · MED (real defect, gated/cloud-only/limited blast radius) · LOW (theoretical/edge/robustness/operability polish) · INFO (clarity/dead-code/observation).
**Status:** CONFIRMED (traced in code, usually repro'd) · GATED (neutralized by a required deployment, e.g. front nginx) · CLOUD (bites the planned multi-tenant cloud, not single-tenant today) · BY-DESIGN (intentional, recorded for awareness).
**Provenance:** Wave 1 = inline + 4-agent parallel. Wave 2 = 15-agent prior-art-benchmarked workflow (ngrok/muxado, frp/yamux, rathole/bore, cloudflared, HTTP-2/yamux, nginx). Wave 3 = 13-agent internals workflow (websockets lib, asyncio, stream state-machines, TLS hardening, supply-chain/CI). `[W2]`/`[W3]` mark wave-of-origin.

**Tally:** 4 HIGH · 19 MED · ~22 LOW · INFO. **Wave 3 added 0 HIGH** — the structural defects are all in the `mux.py` flow-control/teardown cluster + the two edge-path hangs (TLS EOF, CLI fatal-error), now fully root-caused; Wave 3's net-new is a **supply-chain/CI/deploy** class plus operability polish. The campaign has saturated: continued review yields diminishing returns vs. fixing.

## HIGH

### F6 — mux had NO flow control → a stream > 16 MiB to a slower consumer was silently truncated and hung · RESOLVED
- **Where:** `mux.py:43-86` (Stream queue/feed/reset/abort), consumers `server.py:630-645`, `client.py:265-274`.
- **Root cause (now precise, refines the original):** the bug is an **asymmetry between `reset()` and `_abort()`**, not "`_feed` drops a sentinel."
  - Overflow path: `_feed`/`_feed_eof` on a full 256-chunk (~16 MiB) queue `_spawn(self.reset())`. `reset()` sends RESET + `_remove()` but **never enqueues the `None` sentinel into its own queue**. The consumer drains the buffered chunks, then blocks on `stream.read()` (`_incoming.get()`) **forever**.
  - The `mux.py:71` comment ("unblocked by the relay's drain timeout") is **false** for the dominant case: the block is in `queue.get()`, not `writer.drain()`, so the 120 s timeout never arms.
- **Was reachable by normal use:** any download/upload/stream >16 MiB to a phone/throttled client. Reproduced by 3 agents (cap=4, 12 chunks, 5/12 delivered, pump parked).
- **Old aggregate ceiling gap:** `_MAX_STREAMS` (4096) × ~16 MiB ≈ **64 GiB** worst-case buffered per connection; only per-stream and stream-count caps existed.
- **RESOLVED:** the mux now uses per-stream byte-credit flow control (`WINDOW_UPDATE`) instead of a chunk-count queue as the primary control; senders block when credit is exhausted, receivers return credit after bytes drain downstream, frames are chunked to the WebSocket message cap, and both per-stream plus connection-level byte/frame backstops shed non-compliant peers. The receive queue is unbounded because credit windows, not queue size, now bound compliant buffering; overflow/reset paths synchronously deliver an abort terminal. Regression coverage: `tests/test_flow_control.py`, `tests/test_protocol_hardening.py`, `tests/test_transparency.py`, `tests/test_security_limits.py`.
- **[W3] deepened — it was worse than "16 MiB":** the old cap counted **chunks not bytes** (`_STREAM_QUEUE_MAX=256` × ≤64 KiB). For the *small-frame* WebSocket/SSE traffic chute explicitly carries, the effective ceiling collapsed to a few KB, so a **healthy, bursty, progressing** consumer was falsely RESET far below the advertised limit (repro: a consumer draining 1/5 ms got 81/1000 small frames). The old `mux.py:71` comment "unblocked by the relay's drain timeout" was **provably false** once `drain()` succeeded — the block was in `read()`.

### F19 — teardown `_abort()` dropped the sentinel on a full queue → visitor pump + FD + sem slot leak on EVERY agent disconnect mid-transfer · RESOLVED · [W2]
- **Where:** `mux.py:81-86` (`_abort`, `QueueFull → pass`), reached from `mux.py:171-173` (`run` finally); leak surfaces at `server.py:528-535` and the `_visitor_sem` release at `server.py:508`.
- **What:** On the **routine** WSS drop (server restart/SIGTERM, supersede 4003, laptop sleep, Wi-Fi/LTE flap, ping_timeout — i.e. your "relay restart drops tunnels" event), `run`'s finally calls `_abort()` on every live stream. If a stream's queue is full (slow consumer mid-transfer), `_abort` does `put_nowait(None)` → `QueueFull` → **swallows it** ("consumer already has plenty queued; it will stop on its own" — it won't). Consumer drains, parks on `read()` forever; the sibling reader pump is parked on `reader.read()`; the TaskGroup never exits; the `_visitor_sem` slot (1/2048) + FD leak until process restart.
- **Structural root:** server-side visitor pumps live in `_handle_visitor`'s own `TaskGroup`, which is **not** in `mux._tasks` — so `run`'s task-cancel reaches agent-side handlers but never server-side visitor pumps. The droppable sentinel is their *only* teardown signal. Two agents reproduced (consumer hangs >2 s with no rescue; sem exhaustion against a cap-2 sem).
- **RESOLVED:** `_abort()` now closes through the same `_close_local()` teardown path as local reset/close: it marks the stream closed, wakes any sender parked on credit, reconciles aggregate buffer counters, delivers the receive terminal if still open, and deregisters the stream. Because the queue is no longer bounded by item count, the terminal sentinel cannot be dropped by a full queue. Regression coverage: `tests/test_flow_control.py`, `tests/test_protocol_hardening.py`, `tests/test_drain.py`.
- **[W3] deepened — also was reachable in normal operation, and the leak was permanent:** the same sentinel-drop happened on the **overflow path** (`_feed` → `reset()` → `_remove`, no sentinel), not only teardown. The WS stayed healthy (the agent just produced a burst and moved on), so keepalive never reaped it — the visitor conn + `_visitor_sem` slot leaked **permanently** (not the ~40 s ping-timeout bound), and repeated overflows walked the server to 503.

### F20 — edge-TLS swallows a close-delimited response EOF → visitor hangs until its own timeout · RESOLVED · [W2]
- **Where:** `server.py:630-639` (`_pump_stream_to_writer`, the `can_write_eof()` branch), symmetric `client.py:269-271`.
- **What:** Standalone edge-TLS (`--tls-cert/--tls-key`, agent `scheme=https`) + a response delimited by **connection close**, not Content-Length (HTTP/1.0, `Connection: close` w/o length, an SSE/stream that ends by closing). Agent reads `b''`, sends EOF. Server hits `if writer.can_write_eof():` — but over the asyncio **SSL transport `can_write_eof()` is False**, so it takes *neither* branch and returns silently, never closing the visitor. The sibling reader pump stays blocked, the TaskGroup never exits, `finally: _safe_close` never runs. Visitor gets every body byte but **no end-of-response** → hangs.
- **Why it slipped through:** Content-Length/chunked responses are unaffected (client knows the length), so the existing HTTPS tests pass. Verified end-to-end (plain-HTTP delivers clean EOF; edge-TLS hangs with `can_write_eof=False`).
- **RESOLVED:** when a clean peer EOF reaches a downstream writer that cannot half-close (notably asyncio SSL transports), the pump now falls back to a full close so close-delimited HTTP/1.0 bodies and edge-terminated WebSockets observe end-of-response. Regression coverage: `tests/test_https.py::test_edge_tls_close_delimited_response_does_not_hang`.
- **[W3] deepened:** this specifically stranded a `wss://` WebSocket terminated **directly at chute's edge :443** and any close-delimited HTTP/1.0 body — no FIN reached the visitor, and the read hung until the WS ping timeout. Plain `:80` and the nginx topology were unaffected.

### F21 — agent CLI hangs forever (no output, no exit) on a fatal auth/subdomain rejection · RESOLVED · [W2]
- **Where:** `cli.py:129-133` (`agent_main._run`), `client.py:131-135` (`wait_until_ready`, default `timeout=None`), `_FatalError` raised at `client.py:116-118`.
- **What:** `chute http 8000 --token WRONG` (or a taken/over-limit subdomain) → server closes 4001/4002 → `serve_forever()` raises `_FatalError` and stops retrying (correct). But `_run()` does `task = ensure_future(serve_forever())` then `await tunnel.wait_until_ready()` with **no timeout**; on a fatal error `_connected` is never set, so it awaits forever while the background task's `_FatalError` is never retrieved. CLI prints nothing, never exits non-zero. The most common operator error fails **silently**.
- **Why it slipped through:** the only fatal-token test awaits `serve_forever()` directly, **bypassing** `_run()`'s `wait_until_ready` wrapper — the real entry point is untested.
- **RESOLVED:** `_run()` races readiness vs. `serve_forever()`, propagates a fatal serve error, and still retrieves/cancels the background task so there is no orphan-task warning. The CLI exits non-zero with the fatal reason instead of hanging. Regression coverage: `tests/test_cli.py::test_agent_main_wrong_token_exits_nonzero`.
- **[W3] deepened:** the old path also never retrieved the serve task's exception (`await task` was unreachable past the blocked `wait_until_ready`), so on top of the hang asyncio printed a "Task exception was never retrieved" warning at shutdown.

## MED

### F1 — slow-loris: single-tenant first read unbounded + stream opened eagerly · RESOLVED (deepened [W2])
`server.py:521` opened the stream (→ agent dialed local app, **consuming an agent-side FD**) *before any byte*; `server.py:621` `reader.read()` had no timeout. Zero-byte Slowloris pinned server slot **and** local FD. **RESOLVED:** public visitors must send a complete request head within `_FIRST_BYTE_TIMEOUT`; malformed/partial/idle heads fail before `agent.open()`, so no mux stream or local app FD is reserved for a zero-byte/partial visitor. Regression coverage: `tests/test_e2e_localhost.py::test_single_tenant_first_byte_deadline`, `test_partial_request_head_does_not_open_agent_stream`, `test_malformed_request_head_does_not_open_agent_stream`.

### F2 — no intentional idle policy; SO_KEEPALIVE coverage was incomplete · RESOLVED (deepened [W2])
`SO_KEEPALIVE=0` on accepted/local sockets and `asyncio.TaskGroup` lifetime around clean half-close could leave parked pumps. **RESOLVED:** visitor sockets and agent-side local app sockets now get `SO_KEEPALIVE` + Linux `TCP_KEEPIDLE 60 / INTVL 10 / CNT 3` where supported, so a vanished TCP peer is reaped by the OS, and clean response EOF releases the mux stream before the visitor socket itself is closed. The application-level idle policy is now explicit: by default chute does **not** kill quiet-but-live streams, preserving SSE/WebSocket byte transparency; operators can opt into `CHUTE_RELAY_IDLE_TIMEOUT=N`, which resets a visitor stream after N seconds with no relayed bytes in either direction. Regression coverage: `tests/test_e2e_localhost.py::test_response_eof_releases_stream_before_visitor_write_close`, `tests/test_client.py::test_local_app_socket_keepalive_is_enabled`, `tests/test_sockets.py`, `tests/test_security_limits.py::test_relay_idle_timeout_resets_stream_and_closes_visitor`, `tests/test_security_limits.py::test_relay_idle_timeout_counts_bytes_in_either_direction`.

### F22 — RESET is indistinguishable from clean EOF → truncated response delivered as a complete body · RESOLVED · [W2]
`server.py:633-639` / `client.py:268-271`: any RESET (overflow, peer reset, teardown `_abort`) reached the consumer as the **same `None`** a clean half-close produces, so the pump emitted `writer.write_eof()` — a graceful FIN. A response truncated at 16 MiB, or a close-delimited body cut by overflow, was presented to the client as a **normal, complete** end-of-body. **RESOLVED:** `Stream` now carries an explicit receive terminal (`OPEN | EOF | RESET`), `reset_by_peer` is derived from it, and both server/client pumps abort the downstream transport on RESET while preserving clean EOF as a half-close/full close. Regression coverage: `tests/test_flow_control.py`, `tests/test_protocol_hardening.py`, `tests/test_security_limits.py`.

### F23 — `reset()` leaves the Stream usable: post-reset `send()` emits DATA-after-RESET, sibling producer never tears down · RESOLVED · [W2]
`mux.py:53-58` `reset()` `_remove`d the stream but `send`/`send_eof` (`mux.py:43-47`) had no closed-guard. After overflow-reset, the visitor's reader pump could keep calling `stream.send()` and emit DATA for an id the peer was told to drop. **RESOLVED:** `reset()` closes through `_close_local()`, wakes blocked senders, deregisters the stream, and later `send()` raises `_StreamClosed` instead of putting DATA on the wire. Regression coverage: `tests/test_protocol_hardening.py::test_local_reset_closes_send_direction_before_late_data`.

### F24 — agent→local-app connect is unbounded · RESOLVED · [W2]
`client.py:189` `asyncio.open_connection(local_host, local_port)` had **no timeout**. A full listen backlog, a firewalled/blackholed port (SYN dropped), or accept-but-hang pinned the stream for the full OS connect window (minutes) or longer. **RESOLVED:** local-app dialing is wrapped in `_LOCAL_CONNECT_TIMEOUT` and timeout is handled like any other unreachable-local-app failure: log/rate-limit, RESET the stream, and move on. Regression coverage: `tests/test_client.py::test_local_connect_timeout_resets`.

### F25 — chuted ignores SIGTERM → `systemctl stop`/restart KILLs it (exit 143); graceful close is dead code · RESOLVED · [W2]
`cli.py:278-282` catches only `KeyboardInterrupt` (SIGINT); SIGTERM has no handler → process killed, `serve()`'s AsyncExitStack never unwinds, the per-agent 4003 close + mux teardown never run. End-user impact ≈ today's restart behavior (MED, not HIGH), but it (a) **forecloses any future graceful drain/GOAWAY** (the prerequisite — catching SIGTERM — is missing), (b) makes agents wait up to ping_timeout on a half-open socket instead of seeing a clean close, (c) muddies crash-vs-deploy (143 vs 0). **Fix:** `loop.add_signal_handler(SIGTERM/SIGINT)` → shutdown Event → close listeners + abort agents; or minimally `KillSignal=SIGINT` in the unit. **RESOLVED:** `serve()` installs SIGTERM/SIGINT handlers → shutdown Event → close listeners (control with `close_connections=False`) → `mux.drain()` each agent (GOAWAY + bounded wait for in-flight streams, then close `1001`). Protocol v3 added the `GOAWAY` frame (`mux.goaway`/`drain`), and current v4 retains it; the agent drains symmetrically on Ctrl-C/`aclose()`, and the server deregisters a draining agent from routing. Tests: `test_drain.py`.

### F26 — no per-IP visitor cap: one IP can hold all 2048 global slots · RESOLVED · [W2]
`server.py:190,496`: `_visitor_sem` is a single **global** semaphore acquired before any per-IP check (none exists; the only per-IP limiter is control-plane auth). One IP opening 2048 conns → every other visitor gets 503; single-tenant each also pins a stream + local FD (F1). Exposure is real in single-tenant edge mode (sanctioned, no nginx). **Fix:** per-IP visitor counter keyed on `peername`, 503 above a cap, decrement in finally. *(nginx `limit_conn $binary_remote_addr`.)* **RESOLVED:** direct non-loopback visitors now hit a default 64-connection source cap before the global visitor semaphore; source buckets are exact IPv4 addresses or IPv6 `/64` prefixes so temporary-address rotation inside one IPv6 prefix cannot trivially bypass the cap. `CHUTE_MAX_VISITORS_PER_IP=0/off/none/false/unlimited` disables it explicitly. Loopback peers are exempt because Host-routed mode sees nginx as the peer; bundled nginx still applies `limit_conn $binary_remote_addr` with the same 64-connection default for true client-IP accounting.

### F27 — no protocol versioning in hello / ready / frame prefix · RESOLVED · [W2]
`protocol.py` (`!BI`, type+id only), `client.py:152-155` (hello), `server.py:369/408` (ready) carried **no version**. `mux.run`'s elif chain silently dropped unknown frame types, so a future non-optional frame (`WINDOW_UPDATE`) would silently no-op on an old peer. **RESOLVED:** `protocol.VERSION` is negotiated in the JSON hello/ready (`v`), the server rejects missing/mismatched peers with close `4004` before binary frames flow, and the client treats a mismatched ready reply as fatal rather than retrying. Current protocol v4 includes `WINDOW_UPDATE`, `GOAWAY`, and negotiated `flow_window`. Regression coverage: `tests/test_https.py`, `tests/test_multitenant_authz.py`.

### F28 — entire data path + mux emit zero logs → an operator can't explain a hung/truncated/503 report · RESOLVED · [W2]
`server.py:490-666` has no `log.` calls in any `_handle_visitor*`/pump; `mux.py` doesn't import logging. 503/400/no-tunnel/drain-timeout/RESET/overflow are all silent. Byte-transparency forbids logging *payloads* — but not rate-limited structured WARNINGs (peer IP + label + reason + stream id), which carry no payload. **RESOLVED:** server visitor-admission and relay-abort paths now emit rate-limited metadata-only logs keyed by reason/scope, and mux flow-control/protocol violations log reason + stream id + aggregate buffer gauges. Steady-state success remains quiet and payload/request-target/header/body bytes are not logged. Regression coverage: `tests/test_security_limits.py`.

### F7 — non-ASCII token crashes default authorizer → limiter bypass + crash on valid input · RESOLVED
`auth.py:76` previously used `hmac.compare_digest(str(token), …)`, which raised `TypeError` on non-ASCII and skipped `_record_auth_fail`. **RESOLVED:** `StaticTokenAuthorizer` now compares encoded bytes, so non-ASCII token typos are clean unauthorized failures and feed the limiter. Regression coverage: `tests/test_auth.py`.

### F8 — per-IP failed-auth limiter bypassable (IPv6 /64) and not bounded under flood · RESOLVED (deepened [W2])
`server.py:458-487`: keyed on literal IP → /64 rotation = fresh budget + new entry each time; sweep runs only at >4096 keys **and** only deletes all-stale buckets, so under fresh rotation it frees nothing (grew to ~15k). **RESOLVED:** failed-auth buckets now canonicalize IPv6 sources to `/64`, map IPv4-mapped IPv6 to exact IPv4, preserve exact IPv4 to avoid over-throttling unrelated NAT users, and hard-cap the map with oldest-eviction. Regression coverage: `tests/test_security_limits.py`.

### F9 — `requested_subdomain` passed raw/untyped/un-normalized to the authorizer · RESOLVED · CLOUD
`server.py:341`: attacker JSON → int/list/dict (protocol says `str|None`); server normalized only later in `_assign_label` → a DB authorizer could crash or authorize a value ≠ the label actually claimed. **RESOLVED:** the server now extracts and validates `subdomain` before admission: non-string values close `4000`, invalid labels close `4002`, valid labels are lowercased before `TunnelAdmissionRequest` / `AuthRequest` is constructed. Regression coverage: `tests/test_multitenant_authz.py::test_non_string_subdomain_is_bad_handshake_before_authorizer`, `tests/test_multitenant_authz.py::test_invalid_subdomain_is_rejected_before_authorizer`, `tests/test_multitenant_authz.py::test_authorizer_receives_structured_request`.

### F10 — no global ceiling on agents/labels/streams; default authorizer makes it unbounded in multi-tenant · RESOLVED · CLOUD (deepened [W2])
`server.py:383`: only per-account `max_tunnels`. **Default-config path:** `chuted --base-domain …` with the default `StaticTokenAuthorizer` gives every agent account "0" with `max_tunnels=2^62`, so `_authorize_claim` never trips → `_agents`/`_account_labels` grow without bound (FD/memory). `_control_sem` bounds only concurrent handshakes. **RESOLVED:** the relay now has a host-level `max_agents` cap (`CHUTE_MAX_AGENTS` / `--max-agents`, default 1024) enforced under the registration lock before installing a new label; over-cap new labels close retryably (`1013`) and emit `auth_rejected`, while existing-label replacement remains allowed so reconnect/supersede does not break. The static-token Host-routed self-host mode is deliberately preserved because the bundled deployment uses it; the resource-exhaustion risk is bounded by the relay cap instead of by refusing that mode. Regression coverage: `tests/test_multitenant_authz.py::test_global_agent_cap_rejects_only_new_labels`, `tests/test_multitenant_authz.py::test_global_agent_cap_is_retryable_and_does_not_grow_registry`, `tests/test_cli.py`.

### F3 — `allowed_label` defined but never consumed → authorizer can't reserve OR restrict labels · RESOLVED · CLOUD (deepened [W2])
`auth.py:44`, unused in `server.py:386+`. The public Authorizer contract **advertised** label reservation as active behavior the relay didn't implement → a cloud authorizer could set it and silently get nothing; cross-tenant label squatting. **RESOLVED:** `_authorize_claim()` now consumes `allowed_label`: malformed values and labels other than the normalized allowed label fail with `subdomain_not_allowed`; matching reserved labels are accepted. Regression coverage: `tests/test_multitenant_authz.py::test_allowed_label_is_enforced`, `tests/test_multitenant_authz.py::test_malformed_allowed_label_is_rejected_cleanly`.

### F36 — nested-JSON hello raises `RecursionError` that escapes the narrow except → uncaught 1011 + auth-limiter bypass · RESOLVED · [W3]

### F38 — CD forced-command script lives in the tree it deploys, self-mutates on `git reset --hard`, and verifies no signature · RESOLVED · [W3]

## Design themes (the patterns under the bugs)

1. **Flow control is now structural, not a lossy queue substitute.** The old mux lost TCP backpressure at the WebSocket hop and replaced it with a chunk-count queue that could reset, truncate, and hang. **Current state:** per-stream byte credit (`WINDOW_UPDATE`) blocks senders; receivers return credit only after downstream drain; `_MAX_CONN_BUFFERED` / `_MAX_CONN_FRAMES` bound aggregate memory; malicious peer floods hit RESET backstops. Remaining work is tuning/observability, not the original F6/F19 correctness hole.
2. **Teardown now has an explicit stream state, and the duplicated pump mechanics have been extracted.** The old `None` sentinel could be dropped by a full queue; `_RecvState` + unbounded credit-bounded queues fixed the terminal delivery bug. Server/client now share `_relay.py` for read chunking, bounded writer drain, clean EOF, abortive RESET, safe close/reset, flow-control ACK, and optional byte throttle/observer hooks. Remaining asymmetry is caller policy: server idle/account accounting vs agent local-connect/reconnect behavior.
3. **Data-path liveness is deliberate now.** First-byte admission is bounded, vanished visitor/local-app peers get OS keepalive, clean response EOF releases mux streams, and live-but-idle streams have an explicit opt-in no-progress timeout. The default preserves quiet SSE/WebSocket tunnels instead of silently imposing an HTTP-idle assumption.
4. **Failure visibility improved; remaining structure work is now narrower.** RESET now becomes downstream abort, mux/server emit metadata-only warnings/counters, fatal agent handshake errors exit cleanly, local app dial hangs are bounded, opt-in relay idle expiry logs as a relay abort, and cloud admission failures emit metadata-only auth-rejected events. Shared pump mechanics now live in `_relay.py`; remaining visibility work is tuning/observability and the broader simplicity pass.
5. **Duplicated, drifting copies of one concept are being retired.** The relay pump duplication and the old `write_eof` asymmetry are resolved by `_relay.py`; the scheme→URL drift is resolved through one `_https_available` gate; and the stale `random_label()` generator is gone. Server/client still have caller-specific TaskGroup lifetime policy, and `_MAX_WS_MESSAGE` comments remain intentionally mirrored across control-channel endpoints.
6. **Most local scaffolding is now load-bearing; policy gaps moved to explicit extension seams.** CLI bounds, protocol versioning, SIGTERM drain, TLS trust logs, numeric env parsing, `allowed_label`, normalized admission labels, finite leases, local budgets, explicit revocation actions, a local static policy-file backend, a local JSONL event sink, queued best-effort lifecycle/stat events, and relay-global agent ceilings are wired. The remaining product work is higher-level policy implementation, not hidden relay behavior.
7. **[W3] Stream state is now explicit enough for current invariants.** `_RecvState` makes EOF-vs-RESET write-once, reset closes the send side, duplicate OPENs are rejected, and stream ids refuse exhaustion. Future work is a full bidirectional state model only if new protocol features need stricter half-close validation.
8. **[W3] Two hardening postures, now mostly aligned.** The documented nginx-fronted prod path used to get protections the standalone **edge-TLS** mode missed. F45, F14, and F20 are resolved, so standalone edge-TLS now shares the key TLS/session/reload/EOF assurances; keep checking this secondary mode whenever the primary nginx path gains a new hardening behavior.
9. **[W3] Supply-chain assurance now has an explicit end-to-end posture.** Prod installs hash-pinned runtime/build deps, CD verifies signed commits, the release workflow emits provenance plus runtime-SBOM attestations with SHA-pinned actions, and local pre-commit hooks are frozen to commit SHAs with Dependabot refreshes. Remaining work has shifted from supply-chain controls back to data-path structure and product policy.
10. **[W3] Narrow excepts + build-time evaluation used to turn misconfig/protocol-drift into tracebacks or invisible loops** (reinforces Theme 4). `json.loads` `RecursionError` now closes cleanly instead of escaping (F36/F16), env-backed numeric parsing raises one-line CLI errors (F46), and the agent logs its TLS trust mode (F44). For a zero-maintenance daemon, fail-clean-and-say-why is a feature.

### Why these happened — root cause, not excuses

Most reduce to one pattern: **fixed the instance, missed the class.**

1. **Under-generalized fix.** I had the right insight and applied it in one place but not the
   adjacent one. F56 added a *per-stream* tiny-frame cap (a frame costs more than its payload
   bytes) yet I never lifted that byte-vs-object reasoning to the *connection* level (#1). F60
   made `_host_from_head` reject an ambiguous host *name* strictly, but I waved off the *port*
   as "irrelevant to routing" and left `_strip_port` lenient — contradicting the "invalid Host
   → 400" contract I'd just written (#2). *Guard:* after a fix, name the **class** and sweep
   the rest of that surface; re-read the contract just claimed.
2. **Local change, un-audited interaction.** GOAWAY added a 10 s agent drain; I didn't revisit
   the pre-existing `stop()` `join(5)`, so a long drain could orphan the handle (#3). *Guard:*
   a new timeout/limit is a global fact — grep the sites that assumed the old one.
3. **Aspirational comment.** The limiter comment claimed the 4000 path fed the limiter when no
   code did (#5). *Guard:* comments describe what the code *does*; a claimed invariant needs a
   line that enforces it (or a test).
4. **Threat-modeled the common case, not the adversary.** The auth-fail sweep handled "a few
   stale IPs," not the "flood of fresh IPs" the limiter exists to resist (#8). *Guard:* size a
   security bound against its worst-case input.
5. **Catalog-and-defer on the edges.** #4/#6/#9 were already in this ledger (F1, F37–40, F48) —
   known and deprioritized, especially deploy/CI (Theme 9: the measured place is locked down,
   the places that ship are not). *Guard:* infra/supply-chain are trust boundaries, not chores.
6. **Reviewing stale code.** #7 was a false positive against a pre-fix snapshot. *Guard:* verify
   every finding against HEAD; each fix above ships with a test pinning the behavior at HEAD.

### Guardrails added so the class doesn't recur

- **Accounting drift** (#1): `test_connection_buffer_reconciled_on_close` now asserts *both*
  `_buffered` and `_frames` reconcile to 0 — a regression in either counter fails CI.
- **Lock drift** (#4): a CI step re-exports `deploy/requirements.txt` and `git diff --exit-code`s it.
- **Boundaries stated once:** README "Security model" owns the trust model (single-tenant = no
  routing = no routing bugs; multi-tenant = loopback-only, route-per-connection, reject-ambiguous);
  `docs/PROTOCOL.md` owns the wire contract; SECURITY.md owns the report path. No scattered copies.

A follow-up review found 4 more gaps **immediately after** I claimed "docs updated, boundaries

### The deeper miss (why #1 happened right after the retrospective)

My retrospective guard #1 said "sweep the surface." I applied it to *code* but not to *docs*: when I
bumped the version and added `GOAWAY`, I updated the files I was actively editing (PROTOCOL §7/§12,
the handshake steps) and never grepped the README or the Known-Limitations list for the same
cross-cutting facts. "Updated documentation" was verified as "I edited the doc I was in," not "I
swept every surface that states this fact."

**Added guard:** a change to a *cross-cutting fact* (protocol version, a capability gained, a
limitation removed) is not done until `grep` across **all** of README + PROTOCOL + docstrings + the
limitations list comes back consistent. Treat docs like code: name the fact, sweep every surface.

### Guardrails from this batch

- **Transport drift/crashes** now have a property-based net (`test_fuzz_mux.py`), not just examples —
  it would have caught the #1-class accounting drift on its own.
- **The `Budget` model is honest:** all four transport-level fields are enforced and tested:
  visitor slots, reconnect rate, byte-rate throttling, and unread mux-buffer reservations. App-level
  WAF/accounting policies stay absent instead of being advertised as relay controls.
